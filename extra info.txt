How login should work
You actually have two good UI options.
Option A — One Login Page, Role-Based Redirect
This is usually cleaner.
Email
Password
Role:
○ Patient
○ Clinic Staff
○ Admin

            Login

Then:
Patient      → /patient/dashboard
Clinic Staff → /staff/dashboard
Admin        → /admin/dashboard

Option B — Three Separate Login Pages
Your home page can show:
Welcome to CareBridge

[ Patient Login ]

[ Clinic Staff Login ]

[ Admin Login ]

Then you have:
/patient/login
/staff/login
/admin/login

For a hackathon, I would use three role cards on one landing page, leading to three visually different dashboards. That makes the role separation immediately obvious to judges.
Important security point
Don't only hide pages visually. Store a role with every user:
user_id
name
email
password
role

Example:
101 | Rahul | rahul@email.com | **** | patient
102 | Neha  | neha@clinic.com | **** | staff
103 | Admin | admin@app.com    | **** | admin

After login, the backend checks the role.
For example:
if role == patient
   open Patient Dashboard

if role == staff
   open Clinic Dashboard

if role == admin
   open Admin Dashboard

So a patient shouldn't be able to manually type /admin/dashboard and access admin features.
